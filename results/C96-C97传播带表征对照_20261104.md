# C96–C97 传播带表征同留出集对照

本轮没有得到明显提分版本。两个候选均不扩训。现有正式版本仍是 C82。
本轮研究和计算均在 CC 完成，没有继续 C95 接收面数值偏移方向。

## 检验的问题

在已有 294 个 H/TX 物理描述量之外，保留 TX–RX 直线两侧的连续地形与端点逐米细节，能否改善双频 masked RMSE？

新增表征只接收地形 H、TX 像素和待预测 RX 像素。没有标签、有效掩码、其他模型标签信息或 C95 数值偏移输入。
沿 TX–RX 方向设置 64 个归一化采样位置；在 TX、RX 两端各增加 24 个逐米采样位置。
横向距离为 −12、−4、−1、1、4、12 米。采用双线性高度采样，计算相对 TX/RX 连线的垂直间隙。
输出 672 个连续间隙值与 30 个分支摘要，共 702 维。超出地形图的几何比例是输入边界信息，不是目标有效掩码。

## 数据、对照与选择

- FIT：5,508 块地形，7,979 张地图，每图 32 个预抽样位置，共 255,328 个位置。地图覆盖沿用 C72 的每地形最多 8 个 TX 清单；按各地形全部 TX 数与选入 TX 数的比值加权。
- 监测：128 块 TRAIN 留出地形，628 张地图，每图 256 个位置。仅用于本轮选轮数。
- 确认：其余 484 块 TRAIN 留出地形，1,934 张地图，每图 256 个位置。两个频段有效像素分别为 491,358、448,404。
- 所有候选和 C82 都使用完全相同的留出像素与频段掩码。按频段累计 SSE/有效像素数后开方，不平均各图 RMSE。
- 这批 TRAIN 留出地形在历史研究中已使用。它们不是全新盲测集。确认集没有用于本轮候选的梯度、早停或超参数选择。
- 本轮没有读取官方固定 VAL 标签、没有新官方计分、没有网站提交。
- 晋级参考：确认集相对 C82 两个频段各改善至少 0.30 dB，并且地形配对重采样的 95% 改善区间下限为正。最终目标仍是双频官方固定验证各不高于 1 dB。

C96 的 A/B 使用相同的 LightGBM 读出和冻结 C38 基底。
A 输入旧 294 维及 C38 双频输出；B 额外加入传播带 702 维。
每频段最多 600 轮，耐心 80 轮，允许选零修正。低频 A/B 选中 4/3 轮，高频均选零修正。
参数、数据、样本顺序和随机种子保持一致，输入维数是信息对照的变化。

C97 的 A/B 使用相同的 293,218 参数网络。
旧特征经过共享 MLP；连续剖面经过两个深度卷积块；双频查询注意力读取剖面，输出冻结 C38 的双频残差。
A 将六条横向剖面逐位置取均值，再重复为六路；B 保留六条剖面的原始结构。
两组都保留相同的旧 296 维输入和 30 个传播带摘要。两组仅原始横向结构不同。
初始化种子、样本顺序、权重、batch 2048、优化器、1200 步上限及选择规则一致。
每 100 步监测，耐心 300 步。两组均选中第 200 步，第 500 步按规则停止。

两项是冻结 C38 基底上的信息读出筛查，没有修改 C82 的空间分支。不能把筛查失败解释为地形/TX 信息的上限，或证明更强的结构模型必然无效。

## 同面板确认结果

单位为 dB。数值顺序始终为 415 MHz / 5.775 GHz。

| 候选 | 415 MHz RMSE | 5.775 GHz RMSE |
| --- | ---: | ---: |
| C82（相同确认像素） | 2.309509 | 2.601832 |
| C96 旧特征＋树残差 | 2.688783 | 3.033421 |
| C96 加传播带＋树残差 | 2.689033 | 3.033421 |
| C97 横向均值＋剖面网络 | 2.688948 | 3.033610 |
| C97 保留横向结构＋剖面网络 | 2.688943 | 3.033590 |

C96 保留新增传播带，相对相同树读出的旧输入没有可靠改善。
C97 保留横向结构，相对横向均值的改善仅为 0.00000464 / 0.00002062 dB。
C97 的双频改善 95% 区间分别为 [-1.0891856603545413e-05, 1.9553121329740607e-05] 与 [-1.2801117059102474e-05, 4.8310628829095745e-05]，均跨零。
C97 相对同面板 C82 的改善为 -0.379434 / -0.431758 dB，负值表示恶化。
因此，本轮没有扩训依据。没有调整 C82 融合权重，也没有替换正式模型。

## 计算与复核

允许的三张 GPU（实体 1、3、4）均通过完整 UUID 单独检查，两次检查均在 cuInit 返回 999（CUDA_ERROR_UNKNOWN）。
独立系统 Python 的 ctypes 检查也失败，排除了仅由当前 PyTorch 模型代码触发的解释。
strace 显示打开 /dev/nvidia-uvm 返回 EIO（输入输出错误）。内核驱动、实际 libcuda 与 nvidia_uvm 版本均为 550.135。
这定位到模型执行前的系统 CUDA/UVM 故障；具体系统根因尚未确定。
没有重置 GPU、卸载驱动、改服务或停止无关任务。

本轮两个筛查均用 CPU 完成，CUDA_VISIBLE_DEVICES 为空。
PyTorch 的 CPU 反向传播仍自动检查驱动并记录同一 CUDA 初始化警告；所有张量、优化与计分都在 CPU。
C96 两个旧输入读出约 6 秒，两个传播带读出约 25–29 秒。
C97 两组训练与监测分别约 196 / 239 秒。所有候选均已结束，未留下后台训练。

特征通过平地间隙解析对照和转置后横向反序对照。两组网络初始预测与 C38 一致。
选轮数后先保存模型 SHA256 与冻结选择，再统一计算确认分数。
保存的 float32 预测另用 NumPy float64 点积独立计分，与主计分最大差小于 2e-6 dB。

## 正式成绩与待完成工作

C82 既有完整官方固定验证：2.246377 / 2.579150 dB，综合 2.412764 dB。
本轮没有改变这个成绩。双频各不高于 1 dB 的目标未完成。

本次停止 C96/C97 的扩训。GPU 训练受系统 CUDA/UVM 故障阻塞，需要服务器层恢复后才能执行。
没有预设下一种网络必能提分。后续候选仍须先按相同留出面板给出实际双频 RMSE 改善，才进入扩训。
