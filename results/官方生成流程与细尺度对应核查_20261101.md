# 官方生成流程与细尺度对应核查

日期：2026-11-01，Asia/Shanghai。所有新文件位于服务器 CC。本轮只有来源调查、文件解析和 CPU 数值核对；没有训练、模型前向、GPU 计算或新传播仿真。没有读取另一个 AI 的实现、权重、特征或结果正文。

## 结论

**找到了两个可逐像素核对的公开中间结果，但仍未找到仿真原始三角网格、实际 TX 三维坐标、插值前单元数据。细尺度对应问题尚未完全闭合。**

作者公开的三维 Ground Truth 网页内嵌了数值数组。样例 650 对应官方验证样本 `02136_00`，样例 680 对应官方训练样本 `02736_00`。两例的高度图、TX 平面标记和路损图均对应。原方向直接匹配，不需要旋转、翻转或位移。高度最大差小于 0.000002 m；有效像素路损 RMSE 差为 0.016–0.028 dB，主要来自 float16 量化。

这排除了**这两个样本在“公开展示的规则网格结果→比赛数组”之间出现显著新增错位**的解释。它不能检验更早的“物理地形网格→接收三角单元→规则网格插值”。两种展示结果也可能共同继承更早的对应偏差。

对验证样本 `02136_00`，以公开浮点标签替代比赛标签，C4 已保存预测的两个频段 RMSE 分别只改变 0.0000485 / 0.0000606 dB。因此，该样本的数 dB 残差不能用最后的 float16 存储解释。该样本按公开网页可获得性选入，不能代表全部验证地形。

## 官方流程：已证实到哪一步

依据优先级：当前比赛 `metadata.json/README.md` ＞ 固定版本 Sionna RT 1.1.0 源码 ＞ 作者公开说明。2025 年讨论与论文是生成过程的历史说明，不自动等同于当前发布版本的全部细节。

```text
程序生成高度图
  → 构造物理地形三角网格                         [实际顶点/面及变换未发布]
  → 放置 TX；构造地形网格向 z 方向平移 +1 m 的 RX 网格
                                                   [实际 TX 对象坐标、RX 网格未找到]
  → Sionna RT：每个接收三角单元的平均 path_gain    [逐单元/逐种子数据未找到]
  → 取三角中心坐标，scipy griddata(linear) 到 256×256
     并 flipud                                    [精确查询坐标和导出脚本未找到]
  → 多随机种子 np.nanmean 合并
  → 对剩余缺失像素补洞，保存有效掩码
  → 路损约定转换、float16 存储、索引整理          [两例已有逐像素对应证据]
```

1. **接收标签代表单元平均，不是中心点的点接收功率。** Sionna RT 1.1.0 的 `RadioMapSolver` 对每个三角单元做功率面积平均；`cell_centers` 是三顶点坐标的算术平均。单元部分被遮挡时，中心点是否被遮挡与单元平均功率并不等价。源码见 [RadioMapSolver](https://github.com/NVlabs/sionna-rt/blob/v1.1.0/src/sionna/rt/radio_map_solvers/radio_map_solver.py#L28-L43) 与 [MeshRadioMap](https://github.com/NVlabs/sionna-rt/blob/v1.1.0/src/sionna/rt/radio_map_solvers/mesh_radio_map.py#L57-L73)。这证实了观测定义；尚未量出它在本数据中造成多少误差。
2. **要区分两次插值。** 第一次是三角中心到规则网格，正常有效标签也经过它。第二次是对多种子合并后仍缺失的位置补洞。按当前 README，双频最终补洞像素由提供的掩码排除；不能据此认为有效像素完全没有插值。高频最终补洞值为 145 dB，低频用连续插值。[官方数据说明](https://lunarradiomapchallenge.github.io/dataset.html)。本地逐条来源：`../data/metadata.json` 与 `../data/README.md`。
3. **最终存储值的约定明确。** 正路损为 `30 - old_stored_value`。旧值是把无量纲 `path_gain` 传入 `watt_to_dbm` 得到的数值，不能直接当接收功率。新提取的网页标量按该规则转换后与比赛标签匹配。但目前没有完整生成导出代码，不能仅凭文档锁定每个中间阶段究竟在线性功率域还是 dB 域执行平均和插值。
4. 作者本人确认使用抬高的测量网格，并以 `path_gain/cell_centers` 转成二维图；之后用不同随机种子合并以减少空洞。历史讨论最初使用深度 10、10⁹ 射线，后改为深度 100、4×10⁹；本报告的最终参数以当前 metadata 为准。[作者生成过程讨论](https://github.com/NVlabs/sionna/discussions/982)。[原论文第 4 节](https://arxiv.org/html/2509.14559v1#S4)也描述了种子重算与缺失值处理，没有提供完整三角网格导出链。

## 两个公开数值样例的核对

来源：[作者研究网站](https://radiolunadiff.github.io/)。只解析 Ground Truth 网页，没有使用网站模型预测。网页是 VTK.js OfflineLocalView；解码内嵌 ZIP/JSON 和类型数组，不执行网页 JavaScript。

| 公开样例 | 比赛样本 / 划分 | HM 行 / 样本行（均从 0 起） | TX（行,列） | 高度最大绝对差 m | 415 MHz 标签差 RMSE dB | 5.8 GHz 标签差 RMSE dB |
|---|---|---|---|---:|---:|---:|
| 650 | `02136_00` / val | 207 / 807 | (194,160) | 1.90735e-6 | 0.0158317 | 0.0275013 |
| 680 | `02736_00` / train | 2466 / 10166 | (199,46) | 4.76837e-7 | 0.0160056 | 0.0189845 |

核对方法：在全部 6,800 张 train+val 高度图上，用 8 种旋转/镜像方向作粗网格候选筛选，再对每组最接近候选做全像素比较。两个最优对应都是原方向。随后独立核对 TX 平面标记及双频标签；没有用标签挑选高度图对应。

- 样例 650：两个频段有效像素数为 65,285 / 60,207。公开值转为 float16 后，分别有 99.9816% / 99.9950% 与比赛值完全相同。
- 样例 680：有效像素数为 65,073 / 55,887；对应比例为 99.9892% / 99.9946%。
- 未完全一致的少量点说明不能声称两个文件逐字节相同；主要差异符合量化尺度。
- 每张展示网格均覆盖全部 65,536 个唯一整数平面坐标，四边形数为 65,025；没有 NaN。高频无效像素转换后已是 145 dB。这是后处理网格，无法回收插值前值。
- 原始网页及其 Git blob SHA 已保存。四份网页在两频段的高度和点坐标完全一致。

### TX 高度：避免把显示锥体当实测位置

样例 650 的 TX 像素高度是 32.5613976 m，锥体底面为 H−3 m，尖端为 H+7 m。样例 680 也采用同样的显示尺寸。锥体上下端的中点为 H+2 m，但这是一个 10 m 高的显示物体的几何量。没有其生成脚本或实际 `Transmitter.position`，**不能据此改称 TX 是 2 m AGL**。当前仍应保留官方 3 m AGL，标记“实际运行坐标未核实”。

## 现在能判断什么，仍不能判断什么

**已有依据：** 这两个样本没有在最终发布整理阶段新增明显的地形/标签错位；float16 不是它们数 dB 残差的主要来源。生成流程确实存在“单元面积平均→中心坐标插值”的观测变换。用一个网格点的硬遮挡状态去解释标签，可能混淆点可见性与单元平均，但其误差份额尚未测得。

**仍缺证据：** 原三角面的具体划分；RX 平移前后坐标；实际 TX 连续坐标；`griddata` 的查询网格、边缘处理和原点；各阶段功率/dB 变换顺序；逐种子方差。不能据现有后处理数组定量区分细网格对应、传播信息缺失和模型未学会，也不能据此宣布 1 dB 不可达。

要闭合这一步，优先取回 `02136_00` 和 `02736_00` 两例的原始记录即可，不必先索取整个数据集。所需清单见 [原始记录核对清单](/home/chenzhe/work/lunar-pathloss-rm-challenge/CC/audit/generation_alignment_20261101/原始记录核对清单.md)。本轮没有联系组织者或发送任何消息。
