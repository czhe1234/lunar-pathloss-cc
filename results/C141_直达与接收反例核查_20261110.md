# C141：直达与接收计算的训练反例核查

日期：2026-11-10。源目录：/home/chenzhe/work/lunar-pathloss-rm-challenge/CC。

本轮没有得到通过相容性检查的修复版本，也没有新验证分数。已在训练地形完成独立面积积分、原版接收面命中重放、插值对照及射线轨迹检查。原版接收测量确实能降低部分候选直达功率，但仍有不能靠插值或增加非负反射/散射功率解决的反例。因此没有进入原留出集、约束训练或扩训。C82 未改动。

## 1. 范围和判定条件

只用 C136 已冻结 FIT 中的 16 块训练地形，每块一个 TX。共 239 个双频有效像素：

- 47 个“候选直达明显过强，但 C82 已预测较准”的反例，来自 8 块地形。
- 64 个“候选直达过强，C82 也未预测准”的反例，来自另外 8 块地形。
- 同图 128 个普通对照点。

这些点是按错误富集的诊断面板，不是随机样本，也不是留出集成绩。标签和 C82 只用于选点与计分；物理计算脚本只读取地形、TX 和查询位置。16 块地形与原 monitor 的地形交集为 0。239 个点的原始 TRAIN 标签逐值核验一致，两个频段的原始有效掩码均为 1。没有读取官方 VAL 标签。

相容性至少要求：候选直达不能已经超过标签允许的总功率；同时必须预测出弱点的功率，保留普通点。把直达置零虽然能移除下界约束，但不算解决反例。

## 2. 排除了什么错误

固定 C69 候选网格、TX 和接收面，不扫描坐标偏移、世界原点或材料参数。用独立 Mitsuba BVH 做 TX 至接收三角面的遮挡查询，并把每个接收面面积求积从 4 点提高到 16、64、256 点。

- 独立 CPU 的 4 点结果与旧 GPU 直达缓存，最大差 0.00000304 dB。
- 4 点到 256 点：绝对变化中位数 0.00000623 dB；99% 分位 0.000647 dB；最大 0.099884 dB。

因此，在这批反例上，没有发现旧直达积分的实现错误；加密面积求积也不能解释 5—几十 dB 的功率缺口。这个结论限定于本批固定查询，不代表所有遮挡边界都已充分积分。

## 3. 接收测量过程确实改变了功率

使用发布元数据指定的 Sionna RT 1.1.0，以及已有固定 Mitsuba 3.6.2 / DrJit 1.0.3 的 LLVM CPU 环境。保留全局 4e9 Fibonacci 方向的原始编号与权重，只重放目标接收面的候选方向。计算仅含直达，其他传播机制关闭。

这个原版接收面重放与“直接在接收面上反向求面积积分”不同。射线穿过接收面后，原版求解器用 spawn_ray 移开射线起点；后续射线可能跳过其他接收单元。旧 C95 已观察到相关数值效应，本轮是在新的 FIT 反例上重放并检验其功率解释能力。

111 个反例的必要条件检查如下。阈值为候选直达功率比标签允许值高出 1 dB。

| 直达计算/导出规则 | 有限、有信息的反例数 | 无信息的反例数 | 仍违反条件的反例数，两频各自相同 |
|---|---:|---:|---:|
| 独立 256 点面积积分，功率域插值 | 111 | 0 | 111 |
| 原版全部接收面命中，功率域插值 | 97 | 14 | 74 |
| 原版全部接收面命中，dB 域插值 | 25 | 86 | 23 |
| 取正权重供体中最弱的直达功率 | 25 | 86 | 22 |
| 只保留首次接收面命中 | 0 | 111 | 0 |

“无信息”含像素直达为零，或 dB/最弱供体规则中存在正权重零功率供体。它们不能记为修复成功。首次命中规则把 111 个反例全部变为零，故被否决。

22 个有限反例尤其关键：即便任意改变三个固定供体之间的非负插值权重，功率域或 dB 域的凸插值都不能解释标签。增加反射或散射的非负功率只会进一步增强预测。

例如 TRAIN 样本 00452_00 的像素 (248, 6)，两个频段标签为 73.6875 / 96.5625 dB。原版重放后，三个供体中最弱的直达仅为 69.849742 / 92.719820 dB。仍分别过强 3.837758 / 3.842680 dB。供体全部非零，因此不能靠填补零值消除这个反例。

另一个内部像素：00414_00 的 (23, 38)，标签为 88.1250 / 110.6875 dB；最弱供体直达为 70.591718 / 93.461795 dB，仍分别过强 17.533282 / 17.225705 dB。这个反例也不是边缘外推问题。

这些下界是在当前候选场景、固定方向与接收规则下成立。即使稀疏方向查询遗漏了其他贡献，遗漏只会让估计功率更低，不能消除“已有子集功率已经过强”的反例。不能据此声称标签错误或原始输入必然不足。

## 4. 降低直达后，是否真的预测准了功率

把原版重放的直达换入 C136 已保存的逐接收单元传播计算；非直达背景使用已有逐单元值，不加任意常数底噪，不用标签拟合参数。

以下是所选 FIT 点的均匀计分 RMSE，单位 dB。它不是官方验证或无偏全图成绩。

| 点组 | 数量 | C82 | 旧物理计算 | 更换直达，功率域插值 | 更换直达，dB 域插值 |
|---|---:|---:|---:|---:|---:|
| C82 已较准的反例 | 47 | 0.9994 / 0.9879 | 9.0807 / 8.9533 | 5.7694 / 5.6348 | 8.6285 / 8.5287 |
| C82 也漏掉的反例 | 64 | 20.3807 / 22.5117 | 27.5666 / 30.0319 | 21.7756 / 24.2818 | 18.1041 / 19.6678 |
| 普通对照点 | 128 | 0.2675 / 0.3222 | 0.3825 / 0.5031 | 0.3760 / 0.4863 | 0.4296 / 0.5057 |

将“新物理计算减旧物理计算”的差值直接加到 C82 上，也不可靠。功率域版本在 47 个 C82 已较准的反例上恶化到 9.7319 / 9.7850 dB；普通点恶化到 0.3803 / 0.3946 dB。这里没有使用学习门控。这说明这项修正尚不能直接进入提交版本。

上述背景仍来自旧候选传播计算，并非完整原版多跳生成器重放。它的用途是检查“只修直达与末端导出是否已经足够”，不能把它的误差全部归因于直达。

## 5. 为什么只修最后一跳还可能不够

对 3 个剩余反例及同图 3 个普通点，分别用每个供体 16 个固定几何方向追踪射线。每个查询共 48 条方向，保存全部接收面命中和首次地表命中轨迹，不读标签。

- 00452_00 的 (248, 6)：原几何方向瞄准目标单元；经历原版接收面推进后，只有 11/48 条命中预定单元。横向累计偏移最大约 1.02 cm。
- 00997_23 的一个普通点：加入接收面后，48 条射线中 21 条的首次地表三角面改变；地表命中位置最大偏移约 0.315 m。
- 00414_00 的剩余反例：48 条中 10 条的首次地表三角面改变，最大位置偏移约 0.102 m。

这些是定向案例，不是全场景发生率估计。它们证明：在这个数值生成过程里，接收面可能改变后续地表照射；“先按无接收面的理想路径计算地表状态，最后只替换接收算子”未必等价于原版生成器。它们还没有证明这个效应解释了发布标签的剩余全部误差。

理想 Radio Map 的接收面应按单元面积平均不同路径的非相干功率，见 [Sionna 技术报告第 4 节](https://nvlabs.github.io/sionna/rt/tech-report/S4.html)。当前官方代码和发布说明还记录了另一个问题：Russian roulette / stop_threshold 曾在接收面穿越处提前终止射线，见 [官方发布说明](https://github.com/NVlabs/sionna-rt/releases)。本轮直接检查了固定 1.1.0 源码，但没有证据证明比赛启用了这些选项；不能把该已知问题当成本比赛剩余误差的既定原因，也没有升级环境替代旧版本。

## 6. 决定及尚未闭合的点

本轮的相容性检查失败。没有用 monitor 继续选规则，没有启动有无传播一致性约束的网络对照，没有扩训。没有生成新的可提交模型。

已确认的是：面积求积精度不是这批反例的主要原因；原版接收面推进能造成明显功率变化；只修直达、插值或首次命中规则不能同时解释反例和保留普通点。

尚不能唯一确定的是：剩余差异来自实际原始网格、连续 TX 坐标、接收面/发布映射、生成器参数，还是 CPU 与生成器 GPU 后端在掠射交点处的差异。原始生成记录仍缺失。下一项有区分力的检查是对这 22 个固定有限反例做同几何、同方向的 LLVM/CUDA 比对，再决定是否需要重建生成场景；本轮没有借用忙碌 GPU 完成它。不能跳过这项缺口，直接强制网络服从当前绝对直达下界。

当前已核验最佳仍是 C82，官方固定 VAL 的双频 RMSE 为 2.246377 / 2.579150 dB，综合 2.412764 dB。该数字复核自已保存的完整官方算法评分，不是本轮重算或新网站得分。双频各不高于 1 dB 的目标未达到。
